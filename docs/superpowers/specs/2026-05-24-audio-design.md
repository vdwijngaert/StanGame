# Audio — Background Music & Sound Effects

**Date:** 2026-05-24
**Branch:** `worktree-feat-audio`

## Goal

Add procedural background music and sound effects to Stan Dribble Runner. All audio is generated at runtime via the Web Audio API — no asset files, no licensing concerns, no extra bundle weight. Stan can mute via a HUD button, and that choice persists across sessions.

## Why procedural

The game's visuals are 100% Phaser Graphics primitives (no sprites or images). Procedural 8-bit-style audio matches that aesthetic, keeps the build tiny, and avoids the asset-pipeline question entirely. It also stays trivially testable since note scheduling is pure data.

## Architecture

A new pure-JS `AudioSystem` class lives in `src/systems/AudioSystem.js`, following the existing "no Phaser dependency in `systems/`" rule so it can be unit-tested in Node. Phaser scenes call it through a small public API:

```js
audio.unlock();          // call from a user-gesture handler; creates AudioContext on first call
audio.play(name);        // 'ball' | 'hit' | 'levelUp' | 'shieldOn' | 'shieldOff' | 'gameOver'
audio.startMusic();
audio.stopMusic();
audio.toggleMute();      // returns the new muted state
audio.isMuted();
```

The system is instantiated once in `main.js` and registered on the Phaser game registry (`game.registry.set('audio', audioSystem)`) so every scene shares one `AudioContext`. Re-instantiating per scene would create orphaned contexts and audio dropouts.

### Internals

- One `AudioContext`, created lazily on the first `unlock()` call (a tap/click). Browsers block audio creation before a user gesture.
- One master `GainNode` connected to `context.destination`. Mute is implemented as `masterGain.gain.value = 0` (with a 10ms ramp to avoid clicks). Volume changes never destroy nodes.
- Mute flag persisted in `localStorage` under key `stan_runner_muted` (matches the existing `stan_runner_highscore` naming).
- Music sequencer maintains a `nextNoteTime` cursor and schedules ahead using `AudioContext.currentTime`. A `setInterval` (25ms tick) tops up the schedule window. Stopping music cancels the interval and lets currently-scheduled notes finish naturally.

## Sound design

All SFX are short procedural tones, generated by helpers in `src/systems/audio/sfx.js`. Each helper is a pure function `(ctx, destNode, options) => void` that creates the oscillators/gain envelope, schedules them at `ctx.currentTime`, and lets them GC after `stop()`. They never return Promises and never hold references.

| Event | Sound | Trigger site in code |
|---|---|---|
| Ball pickup | Two-note rising blip — square wave C5→E5, 80ms total, exponential gain decay | `GameScene._checkCollisions` ball branch |
| Defender hit / lose heart | Low thud — triangle 200Hz→80Hz over 250ms, tiny white-noise burst layered in | `GameScene._checkCollisions` defender branch (only when not invincible) |
| Level up | Three-note arpeggio — square C5-E5-G5, 60ms each | `GameScene._playLevelUpAnimation` (already exists) |
| Shield pickup | Sine sweep 600Hz→1200Hz + perfect-fifth interval, 300ms, gentle attack | `GameScene._checkCollisions` shield branch |
| Shield expire | Sine 800Hz→400Hz down-chirp, 120ms | When the shield power-up timer expires (not the post-hit invincibility) — the existing shield-end code path in `Player` |
| Game over | Descending sting — square G4-F4-D4-C4, 150ms each | `GameScene` lives-zero branch, before scene transition |

### Music

8-bar chiptune loop in C major, ~120 BPM:

- **Bass:** triangle wave, root-fifth-root-fifth pattern (C2, G2) on each bar's downbeat and beat-3.
- **Arpeggio:** square wave, 8-step pattern over the bar — C, E, G, C, E, G, B, A (one note per eighth).
- Notes are stored as `{ freq, startBeat, duration, wave }` data and scheduled by the sequencer; the note pattern is exported separately so the test can assert beat math without running real audio.
- Music starts when `GameScene.create()` runs and `audio.unlock()` has been called; stops on game-over transition and on mute.

## UI — mute button

A 28×28 speaker icon drawn with Phaser Graphics primitives (matches the no-images rule). Placed at the top-right corner of the screen at `(width − 20, 76)` — just below the score badge so it doesn't crowd the HUD strip. Depth 10 (HUD layer).

- **Unmuted:** speaker silhouette (trapezoid + two arc "waves") in `CONFIG.player.shirtColor` (gold).
- **Muted:** same speaker minus the arc waves, plus a diagonal red line.
- Tappable on touch and clickable on desktop. Hit area is a 44×44 invisible rect for fat-finger friendliness on mobile.
- The same handler also calls `audio.unlock()`, which is what satisfies the browser's first-user-gesture requirement. If the user has never tapped the button, `audio.unlock()` is also called from the joystick's first touch and any keyboard input — so the game is never silent waiting for an explicit mute interaction.
- The button is present in `GameScene`, `BirthdayScene`, and `GameOverScene`, with consistent placement.

A small shared helper, `createMuteButton(scene, audio)`, lives in `src/scenes/visuals.js` next to `drawRoundedGradientPanel` so all three scenes use the same draw code.

## Config

New `CONFIG.audio` block in `src/config.js`:

```js
audio: {
  masterVolume: 0.4,      // 0–1, applied to master gain
  musicVolume: 0.6,       // relative multiplier for music vs. SFX
  musicBpm: 120,
  muteStorageKey: 'stan_runner_muted',
}
```

`masterVolume: 0.4` keeps the procedural tones from feeling shrill at default OS volume.

## Testing

`tests/systems/AudioSystem.test.js` covers logic that doesn't depend on real sound:

- Constructor does not create an `AudioContext` (lazy).
- `unlock()` creates the context once; second call is a no-op.
- Mute state loads from `localStorage` on construction; defaults to `false` when key absent.
- `toggleMute()` flips the flag, persists it, and sets master gain to 0 or back to `masterVolume`.
- `play(name)` is a no-op when muted (the SFX function is not invoked).
- `startMusic()` is idempotent — calling twice does not schedule duplicate notes.
- `stopMusic()` clears the scheduler interval.

Tests use a minimal mock `AudioContext` injected via constructor parameter (`new AudioSystem({ contextFactory })`). The mock returns stub `OscillatorNode` / `GainNode` objects that record `start`/`stop`/`connect` calls. Production code uses `() => new AudioContext()` as the default factory.

A separate `tests/systems/audio/music.test.js` asserts the bass + arpeggio note pattern has the right number of notes per bar, correct beat positions, and that the loop length matches `musicBpm * 8 / 60` seconds — pure data assertions, no audio.

Actual sound output (timbre, mix balance, loop seam) is verified manually in `npm run dev`.

## Open questions / non-goals

- **No volume slider** — single master volume in config is enough for a 10-year-old's game; an in-game slider is YAGNI.
- **No per-event volume** — relative balance baked into each SFX function.
- **No music in BirthdayScene / GameOverScene** — silence between rounds keeps the chiptune from getting tedious. Game-over plays a one-shot sting only.
- **No fade-out on music stop** — abrupt stop is fine for an arcade game; can revisit if it feels harsh in playtest.
